# 通信协议（v0.1 草案）

> 板子 ↔ 上位机 / 蓝牙 共用同一套帧格式。
> 串口参数：**115200 8N1**，无流控。

## 1. 帧格式

```
偏移   0      1      2      3      4 ... 4+LEN-1   4+LEN   5+LEN
     +------+------+------+------+-------------+-------+-------+
     | 0xAA | 0x55 | LEN  | CMD  |  DATA[LEN]  | CRC_H | CRC_L |
     +------+------+------+------+-------------+-------+-------+
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头 | 2 B | 固定 `0xAA 0x55`（`0xAA` 不会出现在数据里？会——所以必须靠 LEN + CRC 双重校验） |
| LEN | 1 B | DATA 字节数，0~48 |
| CMD | 1 B | 命令字，见下表 |
| DATA | LEN B | 负载，小端序（STM32 原生小端，浮点也按小端直接拷贝） |
| CRC16 | 2 B | CRC16-CCITT，**大端**，覆盖范围：`LEN / CMD / DATA`（不含帧头） |

**CRC16 参数**：多项式 `0x1021`，初值 `0xFFFF`，不反转，结果不异或（CRC-16/CCITT-FALSE）。

## 2. 命令字

### 下位机 → 上位机

| CMD | 名称 | LEN | DATA 内容 |
|---|---|---|---|
| `0x01` | 姿态数据 | 8 | `int16 pitch, int16 roll, int16 yaw, uint16 seq`（角度单位 0.01°，seq 递增丢帧检测） |
| `0x02` | 原始数据 | 12 | `int16 gx,gy,gz,ax,ay,az`（调试用） |
| `0x03` | 状态 | 6 | `uint16 state, uint16 err, uint16 vbat_mv` |
| `0x04` | 应答 | 2 | `uint8 ack_cmd, uint8 result`（result: 0=成功，其余=错误码） |

### 上位机 → 下位机

| CMD | 名称 | LEN | DATA 内容 |
|---|---|---|---|
| `0x10` | 设目标角 | 4 | `int16 pitch, int16 yaw`（0.01°） |
| `0x11` | 设 PID | 8 | `uint8 axis(0=pitch,1=yaw), uint8 pad, int16 Kp×1000, int16 Ki×1000` |
| `0x12` | 设滤波系数 | 2 | `uint16 alpha×1000`（0~1000 对应 0.000~1.000） |
| `0x13` | 校准 | 1 | `uint8 mode`（0x01=陀螺零偏校准，0x02=清零点） |
| `0x14` | 启停 | 1 | `uint8 en`（0=停，1=运行） |

> 蓝牙只用 `0x10` / `0x13` 两条就够（手机 App 发十六进制串）。

## 3. 示例

目标：pitch = 12.34°（1234 = `0x04D2`），yaw = -5.67°（-567 = `0xFDC9`）

```
AA 55 04 10 D2 04 C9 FD <CRC_H> <CRC_L>
```

姿态回传：pitch=12.34, roll=-5.67, yaw=180.00(18000=`0x4650`), seq=1

```
AA 55 08 01 D2 04 C9 FD 50 46 01 00 <CRC_H> <CRC_L>
```

## 4. 接收状态机（两端通用）

```
WAIT_HEAD1 ──0xAA──> WAIT_HEAD2 ──0x55──> WAIT_LEN ──> WAIT_CMD ──> WAIT_DATA(0..LEN)
                                                                        │
                                          WAIT_CRC1 ──> WAIT_CRC2 ──> 校验通过 → 分发
```

规则：

1. 任何一步超时（>100 ms 没收到新字节）→ 复位到 `WAIT_HEAD1`
2. 长度非法（LEN > 48）→ 复位
3. CRC 错误 → 丢弃该帧，错误计数 +1（**不静默**，计入状态帧的 `err`）
4. 收到帧头前出现的杂字节直接丢弃

## 5. 错误码（与任务 01 的统一错误码一致）

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | OK | 成功 |
| 1 | ERR_TIMEOUT | 通信超时 |
| 2 | ERR_CRC | 校验失败 |
| 3 | ERR_LEN | 长度非法 |
| 4 | ERR_PARAM | 参数越界 |
| 5 | ERR_BUSY | 设备忙 |
| 6 | ERR_NOT_INIT | 未初始化 |
| 7 | ERR_HW | 硬件故障（I2C 无应答等） |

## 6. 带宽核算

姿态帧 = 2+1+1+8+2 = 14 B，100 Hz → 1400 B/s ≈ 12.6 kbps（含起止位约 14 kbps），
115200 下占用约 12%，余量充足，可同时跑原始数据流。
