# 代码地图

> 目的：拿到任何一个文件，能说出它"归哪层、干什么、被谁调用"。
> 答辩时被问"这段代码干嘛的"，答案都在这。

## 1. 目录 → 职责

| 路径 | 层 | 一句话职责 |
|---|---|---|
| `Core/Src/main.c` | App | 程序入口、任务创建、控制循环、指令处理（**目前最杂，要拆**） |
| `model/pid.c` | Model | 位置式 PID：给误差，算出该补多少 |
| `interface/iuart.h` | Interface | 定义"串口能干什么"（发/收），不涉及硬件 |
| `bsp/uart_stm32.c` | BSP | 用 HAL 实现 `iuart` 接口 |
| `common/frame.c` | 通用 | 打包帧 / 逐字节解析帧（状态机） |
| `common/crc16.c` | 通用 | CRC16 校验 |
| `Core/hardware/mpu6050.c` | 驱动 | 读 MPU6050 寄存器（I2C） |
| `Core/hardware/inv_mpu*.c` | 驱动 | InvenSense DMP：算四元数、输出角度 |
| `Core/Src/freertos.c` | 系统 | CubeMX 生成的默认任务（没改） |

## 2. 主链路（一定要背下来）

```
上电
 └ main()
    ├ HAL_Init / 时钟 / 外设初始化（CubeMX 生成）
    ├ uart_stm32_init(&huart1)      ← 把串口包成 iuart 接口
    ├ 创建 4 个任务
    └ osKernelStart()               ← 从此进入调度器，main 里的 while(1) 永远不执行

SensorTask（5ms）        ControlTask（10ms）           CommTask（等字节）
 ├ 读 MPU6050            ├ 取 g_attitude               ├ iuart_recv 收 1 字节
 ├ 写 g_attitude         ├ PID_Compute                 ├ frame_parser_feed 喂状态机
 └ osDelay(5)            ├ Servo_SetPulse(CCR)         └ 凑齐一帧 → 改目标角/PID
                         └ 每 10 次发一帧姿态
```

## 3. 五个必会函数

### ① `StartDefaultTask(void const *argument)`
- **吃什么**：无（任务入口）
- **干什么**：每 10ms 调一次 `Gimbal_Update()`，用 `HAL_GetTick()` 做节拍
- **吐什么**：无返回值，靠副作用（改舵机脉宽）

### ② `Gimbal_Update(void)`
- **吃什么**：`g_attitude`（姿态）、`pid_pitch/pid_yaw` 的目标值
- **干什么**：算误差 → PID → 转成脉宽 → 写舵机；每 10 次发一帧遥测
- **吐什么**：无返回值，副作用是写 TIM3 的 CCR1/CCR2

### ③ `PID_Compute(PID_t *pid, float feedback, float dt)`
- **吃什么**：目标值（存在 pid 结构里）、当前测量值、控制周期
- **干什么**：`误差 = 目标 - 当前` → P/I/D 三项 → 限幅
- **吐什么**：`float`，单位是微秒（舵机要补多少）

### ④ `Servo_SetPulse(uint32_t channel, int16_t pulse_us)`
- **吃什么**：通道（TIM_CHANNEL_1/2）、脉宽（500~2500us）
- **干什么**：先限幅，再写 `__HAL_TIM_SET_COMPARE`
- **吐什么**：无，副作用是改变 PWM 占空比

### ⑤ `StartCommTask(void const *argument)`
- **吃什么**：串口字节流
- **干什么**：`iuart_recv` 收字节 → `frame_parser_feed` 解析 → `Comm_HandleFrame` 执行
- **吐什么**：改 `pid.目标`、改 PID 参数、回 ACK 帧

## 4. 两条数据流

```
【控制流】MPU6050 →(I2C)→ 姿态角 → g_attitude → PID → 脉宽 → 舵机
                         5ms            10ms

【指令流】电脑/手机 → 串口 → 字节 → 状态机 → 命令 → 改参数 → ACK 回去
```

## 5. 三个容易混淆的点

| 容易错 | 正确 |
|---|---|
| `osDelay(5)` 和 `HAL_Delay(5)` | 前者让出 CPU，后者死等（别在任务里用 HAL_Delay） |
| `g_attitude` 是普通变量 | 是 `volatile`，两个任务共享，不要加锁（32 位读写原子） |
| `main.c` 里的 `while(1)` | `osKernelStart()` 之后永远执行不到，别往里写代码 |
