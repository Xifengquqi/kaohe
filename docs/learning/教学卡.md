## 卡片 01 · 状态机

**是什么**：程序不从头跑到尾，而是记住"我现在在哪一步"，每来一个输入决定下一步去哪。

**项目里哪用**：`common/frame.c` 的串口收帧。字节是一个一个来的，任何时刻都不知道一帧从哪开始。

**5 分钟练习**：在纸上画 7 个圈（HEAD1/HEAD2/LEN/CMD/DATA/CRC_H/CRC_L），箭头写"收到什么字节"。

**自测**
1. 收到 `AA AA 55` 会怎样？（答：第二个 AA 让它留在 HEAD2，不会错乱）
2. LEN 收到 0xFF 怎么处理？（答：超过 48 直接丢弃，回 HEAD1）
3. CRC 错了为什么回 HEAD1 而不是继续？（答：后面可能已经错位，必须重新找帧头）

## 卡片 02 · 串口（UART）

**是什么**：两根线，一根发一根收，按约定的速度一位一位传。不需要时钟线，靠双方约定波特率。

**项目里哪用**：`bsp/uart_stm32.c`，115200 8N1，PA9 发、PA10 收。

**三个必须记住的点**

| 点 | 为什么 |
|---|---|
| **TX 接 RX，RX 接 TX** | 一头说话，另一头得听着；顺接就是两个人在自说自话 |
| **必须共地** | 电压是相对 0V 说的，没有共同参考就分不清 0 和 1 |
| **波特率必须一样** | 115200 是"每秒 115200 位"，两边不一致就全部乱码 |

**算一笔账**：一帧 14 字节，每字节 10 位（1 起始 + 8 数据 + 1 停止）= 140 位，115200 下约 **1.2 ms**。100 Hz 发一帧占 12% 带宽 → 余量很足，这就是协议里定 14 字节的底气。

**自测**
1. 115200 下一个字节占多少时间？（答：10/115200 ≈ 87 µs）
2. 为什么串口比 I2C 简单？（答：没有地址、没有应答，点对点直连）

## 卡片 03 · HAL 库到底替你做了什么

**是什么**：`HAL_UART_Init()` 不是魔法，它只做四件事：

1. 打开 GPIOA 和 USART1 的时钟
2. 把 PA9 配成复用推挽、PA10 配成上拉输入
3. 算 BRR（波特率分频）= 72 MHz ÷ 115200 ≈ **625**
4. 置位 CR1 的 UE/TE/RE（使能、发送、接收）

**我是怎么验证的**（这就是"看寄存器"的方法）：烧录后用 J-Link 读三个寄存器：

| 寄存器 | 读到的值 | 说明 |
|---|---|---|
| USART1_CR1 (0x4001380C) | `0x200C` | UE/TE/RE 都置了 → 串口确实初始化了 |
| USART1_BRR (0x40013808) | `0x271` = 625 | 625 = 72 MHz / 115200 ✓ |
| USART1_SR (0x40013800) | `0xC0` | TXE/TC → 发送器空闲 |

**结论**：不用猜"串口到底有没有初始化"，读寄存器就知道。**这就是硬件调试和纯软件调试最大的区别。**

**自测**
1. BRR 为什么是 625，而不是 312？（答：USART1 挂在 APB2 = 72 MHz，不是 APB1 的 36 MHz）
2. 如果 BRR 算错，现象是什么？（答：全是乱码）

## 卡片 04 · 我是怎么排查"串口没数据"的（方法卡）

遇到"没反应"，按这个顺序查，**从后往前**：

```
电脑收到数据了吗
  └→ 没有 → 板子发了吗？（读 USART1 的 SR：TXE 有没有在动）
       └→ 没发 → 程序走到发送代码了吗？（读变量：mpu_ready=0 → 提前 return 了）
            └→ 为什么没走到？（读 I2C 状态：AF 标志 = 从机不应答 → 硬件线松了）
```

**关键**：每一步都用**可观测的证据**（寄存器、变量、字节数）判断，不靠猜。

这次就是：串口寄存器正常 → 变量 `mpu_ready=0` → I2C 报 AF → 发现 MPU 的线被碰松。

**自测**
1. 如果电脑收到的是乱码而不是没数据，你会先查什么？（答：波特率、共地）
2. 如果 `mpu_ready=1` 但电脑还是没数据，查什么？（答：TX/RX 是否交叉、CH340 是否选对端口）
