## 卡片 02 · 串口（UART）

**是什么**：两根线，一根发一根收，按约定速度一位一位传。没有时钟线，靠双方约定波特率。

**项目里哪用**：`bsp/uart_stm32.c`，115200 8N1，PA9 发、PA10 收。

**三个必须记住的点**

| 点 | 为什么 |
|---|---|
| TX 接 RX，RX 接 TX | 一头说话，另一头得听着；顺接就是自说自话 |
| 必须共地 | 电压是相对 0V 说的，没有共同参考就分不清 0 和 1 |
| 波特率必须一样 | 双方节奏不一致，收到的全是乱码 |

**算一笔账**：一帧 14 字节 × 10 位/字节 = 140 位，115200 下约 1.2 ms。100 Hz 发一帧占 12% 带宽——这就是协议定 14 字节的底气。

**自测**
1. 115200 下一个字节占多少时间？
2. 为什么串口比 I2C 简单？

## 卡片 03 · HAL 到底替你做了什么

`HAL_UART_Init()` 不是魔法，只做四件事：

1. 打开 GPIOA、USART1 的时钟
2. PA9 配复用推挽，PA10 配上拉输入
3. 算 BRR = 72 MHz ÷ 115200 ≈ 625
4. 置位 CR1 的 UE / TE / RE

**我当时的验证**（用 J-Link 读寄存器）：

| 寄存器 | 值 | 说明 |
|---|---|---|
| USART1_CR1 | `0x200C` | UE/TE/RE 都置了 → 串口确实初始化了 |
| USART1_BRR | `0x271` = 625 | 625 = 72 MHz ÷ 115200 ✓ |
| USART1_SR | `0xC0` | TXE/TC → 发送器空闲 |

**结论**：不用猜"串口有没有初始化"，读寄存器就知道。这是硬件调试和纯软件调试最大的区别。

**自测**
1. BRR 为什么是 625 而不是 312？
2. BRR 算错会有什么现象？

## 卡片 04 · 排查"没反应"的方法（最常用的一张）

从后往前查，每步都要有**可观测证据**：

```
电脑收到数据了吗？
 └ 没有 → 板子发了吗？（读 USART1 的 SR：TXE 在不在动）
      └ 没发 → 程序走到发送代码了吗？（读变量 mpu_ready）
           └ 没走到 → 为什么？（读 I2C 的 SR1：AF=1 从机不应答）
                └ 结论：MPU 的线松了
```

这次的真实路径就是：串口寄存器正常 → `mpu_ready=0` → I2C 报 AF → 发现线被碰松。

**自测**
1. 收到的是乱码而不是没数据，先查什么？
2. `mpu_ready=1` 但电脑没数据，查什么？

## 卡片 05 · 为什么串口要放在线程里

**不这么做**：`ser.read()` 放在界面线程，读的时候界面卡住，拖窗口没反应。

**原因**：`read()` 是阻塞的，没数据就一直等，界面线程被占住就没法响应鼠标键盘。

**做法**：串口线程只管"收字节 + 拆帧"，收到一帧发个信号；界面线程收到信号更新数据。

对应代码：`SerialReader(QtCore.QThread)` + `frame_ready = QtCore.pyqtSignal(...)`。

**自测**：把 `self.reader.start()` 换成直接调 `self.reader.run()`，窗口会怎样？

## 卡片 06 · 怎么读寄存器

**寄存器 = 一个数，每一位管一件事**，所以要拆成二进制看。

例：`USART1_CR1 = 0x200C`

```
0x200C = 0010 0000 0000 1100
                        ││└─ bit2  RE  接收使能
                        │└── bit3  TE  发送使能
                        └─── bit13 UE  串口总使能
```

人话：**串口开了，发送开了，接收也开了。**

**三个查位定义的地方**

| 方法 | 适合 | 怎么做 |
|---|---|---|
| Ozone 的 Peripherals 视图 | 新手首选 | `View → Registers → Peripherals → USART1`，自动拆位、标名字 |
| 参考手册 RM0008 | 最权威 | 搜 "USART_CR1"，有完整位表 |
| HAL 头文件 | 写代码时 | `stm32f103xb.h` 搜 `USART_CR1_UE` |

**项目常用寄存器速查**

| 寄存器 | 看什么 | 正常值 |
|---|---|---|
| USART1_CR1 | UE/TE/RE | `0x200C` |
| USART1_BRR | 波特率分频 | `625` |
| USART1_SR | TXE/TC | `0xC0` |
| I2C1_SR1 | AF（应答失败） | `0x200` = 出错 |
| I2C1_SR2 | BUSY | `0` = 空闲 |
| GPIOB_IDR | bit6/7 = SCL/SDA 电平 | 都高 = 总线空闲 |

**自测**：`SR = 0xC0` 里的 TXE 和 TC 分别是 1，意味着什么？

## 卡片 07 · 分层：BSP / Module / App

| 层 | 管什么 | 例子 |
|---|---|---|
| Applications | 业务：云台怎么转、状态怎么切 | `app/gimbal` |
| Modules | 器件语义：传感器、舵机、蓝牙 | `module/mpu6050` |
| BSP | 板级封装：串口、I2C、CAN | `bsp/uart_stm32.c` |
| HAL / LL | 厂商库 | `Drivers/` |

**铁律**：依赖只能向下；App 和 Module 里不许出现 `HAL_`。

**为什么**：换芯片时只改 BSP，上面一行不动。

## 卡片 08 · 怎么做设计取舍

每个决定写三行：

```
选项 A：…… 代价：……
选项 B：…… 代价：……
我选 B，因为……（成本 / 风险 / 时间）
```

**例子：帧头为什么用两个字节？**
- A：单个 `0xAA` —— 代价：数据里出现 `0xAA` 就误判
- B：`AA 55` + CRC —— 代价：每帧多 1 字节
- 选 B：多 1 字节，换掉一整类错误

**自测**：为什么发送用阻塞而不是 DMA？（提示：14 字节 vs 控制周期 10 ms）
